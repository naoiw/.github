# AI開発エージェント共通ルール

## 既定値
**特別な指示がない場合、naoiw配下の各リポジトリでは本 `naoiw/.github` の共通開発規約を既定値として扱うこと。**

優先順位: (1) 今回の明示的なユーザー指示、(2) 作業対象リポジトリのREADME・docs・AGENTS.md・ツール設定・既存実装、(3) 本リポジトリの共通規約。矛盾する場合は優先順位に従う。規約を読むために外部リポジトリへのアクセスが必要な場合は実際に取得し、取得できなければ「読んだ」と主張しないこと。

## 作業前
- 対象の既存コード・設定・README・docs、関連Issue（open/closed）、PR、ブランチを確認する。
- 既存の設計・ライブラリ・フォルダ構成・CSS方針を尊重する。
- 重複するIssue/PRを作らず、既存の作業を継続できるならそれを優先する。
- 依頼の範囲を守る。「Issueのみ」「コード変更しない」「mainにマージしない」「開発版だけ」などは厳守。

## 実装
- 無関係なリファクタリング、依存追加、破壊的変更、不要な機能を行わない。
- 既存機能・公開URL・データ互換性を維持する。破壊的変更が必要なら明確に報告する。
- UIに開発メモ、作業状況、次のタスク、GitHubリンク等を依頼なく表示しない。
- 日本語UIの既存表記、スペーシング、レイアウトをなるべく統一する。
- 必要性がないテストコード・ドキュメント・設定ファイルを増やさない。既存のテスト構成は勝手に削除しない。
- ライセンスの一律変更、公開情報・秘密情報の漏出、他リポジトリの設定変更を避ける。

## 検証・報告
- 変更に合わせてLint・型チェック・関連テスト・ビルド・ブラウザ確認を実施する。
- 実行できない検証があれば未確認と明記する。実施したコマンド・結果を要約する。
- 完了した変更、未対応、リスク、PR URL、ブランチ、マージ状態を正確に伝える。
- ローカルでのプレビュー不能を理由に、無断で本番にデプロイしない。

## GitHub
[開発フロー](GITHUB_FLOW.md) に従う。原則、短命ブランチ→PR→検証→明示的に承認されたマージ。不要なdevelopを追加しない。

## 技術スタック / CSS
新規React/TypeScriptアプリはpnpmを標準とし、現行のWebスターターはpnpm 9.14.2と`pnpm-lock.yaml`を使う。**既存アプリの依存管理方式は勝手に変更しない。**

[技術スタック](TECH_STACK.md)、[UI・CSSガイド](UI_STYLE.md)、[構成方針](REPOSITORY_STRUCTURE.md) に従う。ただし既存リポジトリの選定が優先。

## AIツールへ渡す方法
本ファイルは他リポジトリへ**自動継承されません**。各リポジトリの `AGENTS.md`、`.cursor/rules/*.mdc`、`.github/copilot-instructions.md` などへ明示的に参照を配置してください（[導入用ファイル](../templates/README.md)、[同期手順](AI_RULE_SYNC.md)）。
