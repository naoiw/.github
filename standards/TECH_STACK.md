# 新規プロジェクトの技術スタック既定値

**既存リポジトリの技術構成・パッケージマネージャーを変更する指示ではありません。** 特別な指定がない**新規開発**の選定指針です。

## TypeScript / ReactのWebアプリ
- 言語: TypeScript（strict）／React（関数コンポーネント）
- ビルド: Vite（単純な静的サイト向け）。SSR・認証・サーバーAPIが必要な場合は案件に合わせて判断。
- ランタイム: プロジェクトに必要なサポート中のNode.js LTS。初期値の例は Node.js 26。 `.nvmrc` と `package.json#engines` を整合させる。
- 依存管理: 新規の小規模アプリはnpmを既定候補とする。既存のnpm/pnpm/yarnは維持し、lockfileは1種類にする。
- 品質検証: ESLint、TypeScript型チェック、既存のテスト基盤、Viteビルド。新規アプリでは必要なものから導入。
- コマンド名: `dev`, `build`, `preview`, `lint`, `typecheck`, `test` を可能な範囲で統一。
- GitHub Pagesを使うときはリポジトリ名を含むbase pathを正しく設定し、mainのみかmain+developかを選択する。
- 無目的なUIライブラリ、状態管理、CSSフレームワークの導入を避ける。

初期構成やCSSの出発点には [React/Viteスターター](../templates/web-react/) を用意しています。既存プロジェクトへの一律移植は行いません。

## C / 組み込み
- ベンダーSDK、コンパイラ、ターゲットMCU、既存ディレクトリ配置を優先。
- 既存コーディング規約とDoxygenの責務分担を優先。Webアプリ向けの標準を流用しない。
- 変更対象のハードがない場合は、実機試験を実施済みと報告しない。

## Rustなど
- Cargoなど当該言語の標準ツールと既存設計を優先。
- 言語選定が実験目的の場合、TypeScriptへ勝手に移植しない。

## ライセンス
詳細は [ライセンス運用規約](LICENSING.md) も参照。
- 新規の自作コードを公開する場合、指定がなければMITを候補として提示する。
- 実際の `LICENSE` は各リポジトリに個別配置する。naoiw/.githubにはデフォルトライセンスの自動適用機能はない。
- 既存のApache 2.0などをMITへ無断変更しない。外部データ・素材の条件は個別に確認する。
