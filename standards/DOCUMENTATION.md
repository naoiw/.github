# README / docsの既定ルール

READMEは**現在利用可能な機能と使い方**を記載し、実装予定をUIやREADMEへ勝手に増やさない。未実装課題はIssueで管理する。

## READMEの推奨項目
- 概要・用途
- 本番URL（存在する場合）と開発プレビューURL（明示的に公開している場合）
- 主な機能と操作方法
- 技術スタックと動作環境
- セットアップと検証コマンド
- ディレクトリ構成へのリンク（必要な場合）
- ライセンスと第三者素材の帰属表記

## docsの役割
- `docs/ARCHITECTURE.md`: 実装構成と設計上の責務
- `docs/DEVELOPMENT.md`: ブランチ・CI・デプロイ・開発手順
- 仕様が複雑な場合だけ機能ごとのドキュメントを追加
- 不要なダミードキュメントや重複説明を増やさない

既存README/docsの固有仕様を保ったまま更新する。READMEの体裁統一のために機能説明を消さない。
